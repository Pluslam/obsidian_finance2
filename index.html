Day 1 · 約 45–60 分鐘

認識第二大腦與安裝 Obsidian

🎯 學習目標

  • 明白「第二大腦」是什麼，以及為什麼一人公司特別需要它
  • 理解 Tiago Forte 的 CODE 與 PARA 核心概念
  • 成功下載、安裝 Obsidian 並建立第一個 Vault

📖 白話解釋

你的大腦擅長「想」同「連結」，但唔擅長「記住大量細節」。第二大腦就係一個外部系統，幫你把有價值的知識、想法、資料全部收納，等你需要時可以快速找回並重新組合。

Tiago Forte 提出兩個核心框架：

CODE（流程）：Capture（捕捉）→ Organize（整理）→ Distill（提煉）→ Express（表達）
PARA（結構）：Projects（專案）· Areas（領域）· Resources（資源）· Archives（封存）

對於一人公司來說，第二大腦可以同時管理多個業務的客戶資料、財務筆記、活動計劃、學習心得，全部用同一套系統。之後我們會特別用「多公司財務對帳」作為真實場景示範。

真實場景：電腦螢幕開住 Obsidian，旁邊放住一本手寫筆記同咖啡杯，自然光從側邊照入，淺景深突出筆記內容

🛠️ 操作步驟

  1. 去 obsidian.md 下載對應你系統嘅版本（Windows / macOS / Linux）
  2. 安裝後打開，選擇「Create new vault」
  3. Vault 名稱建議用：第二大腦 或 MySecondBrain
  4. 選擇一個你容易搵到嘅資料夾位置
  5. 點 Create，你就會見到一個空白嘅工作區
  6. 按 Ctrl+N（Mac 用 Cmd+N）建立第一個筆記，寫上「歡迎來到我的第二大腦」

⚠️ 常見錯誤

  • 一開始就裝大量 Community Plugins → 容易混亂，先用核心功能
  • Vault 放喺雲端同步資料夾直接同步 → 可能造成衝突
  • Vault 名稱用英文空格或特殊符號 → 保持簡單

✍️ 練習

今天完成：
1. 成功安裝 Obsidian
2. 建立名為「第二大腦」的 Vault
3. 寫下第一個筆記，內容包含你目前最想整理的 3 個業務或生活領域

📌 重點回顧

  • CODE 是流程，PARA 是結構

Day 2 · 約 50–70 分鐘

Markdown 基礎：寫出乾淨可讀的筆記

🎯 學習目標

  • 掌握最常用的 Markdown 語法
  • 能寫出標題、列表、粗體、連結、引用
  • 理解「純文字 + Markdown」為什麼適合長期知識管理

📖 白話解釋

Obsidian 用 Markdown 作為筆記格式。好處係：你寫嘅內容永遠係純文字，十年後仍然可以用任何編輯器打開，唔會被軟體鎖定。

# 標題1　## 標題2　**粗體**　*斜體*
- 列表　1. 有序　[[筆記連結]]　> 引用

🛠️ 操作步驟

  1. 建立新筆記，命名為「Markdown 練習」
  2. 練習寫出：一個大標題、兩個小標題、一段粗體重點、一個無序列表、一個有序列表
  3. 用 [[ ]] 嘗試連結到你昨天寫嘅筆記
  4. 儲存後，喺預覽模式睇吓效果

⚠️ 常見錯誤

  • 標題後面冇空格（#標題 → 應該 # 標題）
  • 過度用標題，導致結構混亂
  • 把所有內容都塞進一個超長筆記 → 之後會難找

✍️ 練習

寫一個「今日學習記錄」筆記，包含：日期、今日學到的 3 件事（用列表）、一個自己的感悟（用粗體標出關鍵句）、並用 [[ ]] 連結到昨天的筆記。

📝 測驗（單選）

問題：在 Obsidian 中建立內部筆記連結的正確寫法是？

📌 重點回顧

  • Markdown 是第二大腦的「通用語言」
  • 先掌握標題、列表、粗體、[[連結]] 就足夠開始
  • 筆記要短而清晰，方便日後「提取」
Day 3 · 約 50–70 分鐘

雙向連結與 Graph View：讓知識開始「長」起來

🎯 學習目標

  • 熟練使用 [[雙向連結]] 與 Backlinks
  • 理解 Graph View 如何顯示知識網絡
  • 建立至少 5 個互相連結的筆記

📖 白話解釋

傳統資料夾係「分類」，但第二大腦強調「連結」。當你用 [[ ]] 把兩個概念連起來，Obsidian 會自動記住「邊個提過邊個」，形成雙向關係。

Graph View 可以即時睇到你的知識網絡。一開始可能只有幾個點，但隨著你持續寫同連結，圖會變得越來越有價值——這正是「提取記憶」的關鍵。

真實場景：電腦螢幕顯示 Obsidian Graph View，點與線交織成網絡，旁邊有手寫筆記紙張，自然光，淺景深

🛠️ 操作步驟

  1. 建立筆記「PARA 方法」並簡單寫下四個字母意思
  2. 建立筆記「CODE 方法」並寫下四個步驟
  3. 在兩個筆記中互相用 [[PARA 方法]] 與 [[CODE 方法]] 連結
  4. 再開兩個與你業務相關的筆記（例如「客戶跟進」或「活動策劃」），並連結回 PARA
  5. 打開 Graph View，觀察連線
  6. 在右側面板打開 Backlinks，看看有哪些筆記引用了當前筆記

⚠️ 常見錯誤

  • 為連結而連結，沒有真正關聯
  • 一開始就追求「完美圖譜」→ 圖譜係結果，唔係目標
  • 忽略 Backlinks 面板

✍️ 練習

建立一個「知識種子」筆記，寫下你最近學到的一個重要概念，然後強制用 [[ ]] 連結到至少 3 個已有或新建的筆記。完成後打開 Graph View 截圖保存。

📝 測驗（單選）

問題：在 Obsidian 中，Backlinks（反向連結）的主要作用是？

📌 重點回顧

  • 連結 > 分類，這是第二大腦與傳統資料夾最大的不同
  • Graph View 是視覺化你思維網絡的工具
  • 持續寫 + 持續連，知識會自然「長」出來
Day 4 · 約 60–80 分鐘

CODE 上半部：Capture 與 Organize（PARA）+ Properties 入門

🎯 學習目標

  • 理解「只捕捉會產生共鳴的東西」
  • 學會用 PARA 四個資料夾快速整理筆記
  • 初步認識 Properties（屬性），為之後財務與儀表板打基礎

📖 白話解釋

Capture（捕捉）：只存「會令你產生共鳴、覺得有用」的內容。

Organize（整理）：用「可行動性」而非「主題」來分類。PARA 就係為此而生：

Projects：有明確目標同期限的短期工作
Areas：需要長期維護的責任領域（財務、健康、客戶關係）
Resources：感興趣的主題資料
Archives：已完成或暫不需要的項目

另外，Obsidian 的 Properties（筆記屬性）可以幫你為每篇筆記加上「標籤式資訊」（例如公司、狀態、金額），之後用 Bases 做成可篩選儀表板，對多公司財務特別有用。

🛠️ 操作步驟

  1. 在 Vault 根目錄建立四個資料夾：01-Projects、02-Areas、03-Resources、04-Archives
  2. 在 01-Projects 下建立 2–3 個你目前真實進行中的專案資料夾
  3. 在 02-Areas 下建立「財務」「健康」「學習」「客戶關係」等
  4. 把已有筆記根據「它現在最能幫助哪個專案或領域」移到對應位置
  5. 建立一個「Inbox」筆記或資料夾，專門放剛捕捉、尚未整理的內容
  6. （進階嘗試）在一篇筆記按 Ctrl+; 或點右上角加 Properties，試試加入 company 或 status

⚠️ 常見錯誤

  • 用主題（例如「行銷」「技術」）取代 PARA → 會令行動性下降
  • Projects 資料夾永遠不清理 → 定期把完成的移到 Archives
  • 捕捉太多無用資訊 → 記住「共鳴」原則

✍️ 練習

列出你目前真實存在的 3 個 Projects 與 4 個 Areas，並在 Obsidian 中建立對應資料夾與至少一個代表筆記。把一個舊筆記移到正確的 PARA 位置。嘗試為一篇筆記加上 1–2 個 Properties。

📝 測驗（單選）

問題：根據 PARA，「正在準備 9 月的比賽活動」應該放在哪一類？

📌 重點回顧

  • Capture 只收「有共鳴」的東西
  • Organize 用可行動性（PARA）而非主題
  • Properties 是之後做儀表板與財務追蹤的基礎
Day 5 · 約 50–70 分鐘

CODE 下半部：Distill 與 Express

🎯 學習目標

  • 學會把長筆記提煉成「未來自己能一眼看懂」的精華
  • 理解 Express 才是第二大腦的最終目的
  • 完成一次從捕捉到輸出的完整小循環

📖 白話解釋

Distill（提煉）：原始筆記通常太長。提煉的目標係「找到本質」，讓未來的你在 10 秒內就能抓到重點。常用方法：粗體關鍵句、寫一句話總結。

Express（表達）：第二大腦不是終點，而是燃料。最終要輸出——寫文章、做簡報、回覆客戶、做決策、出財務總覽。

一人公司場景：你捕捉了一篇關於「幼稚園銷售異議處理」的文章 → 整理到對應 Project → 提煉出 5 個關鍵話術 → 直接用在下次見校長的腳本裡。這就是完整的 CODE。

🛠️ 操作步驟

  1. 找一個你之前寫的較長筆記
  2. 在頂部加一行：> 一句話總結：……
  3. 把最重要的 2–3 句用 **粗體** 標出
  4. 思考：這個筆記可以幫助我產出什麼？並寫在筆記最下方

⚠️ 常見錯誤

  • 只收集不提煉 → 未來自己仍然看不懂
  • 提煉過度，失去原始脈絡
  • 永遠不 Express → 系統會變成「知識墳場」

✍️ 練習

選擇一個已有筆記，完成 Distill（一句話總結 + 粗體關鍵句）。然後用這個筆記實際產出一個小東西：可以是 WhatsApp 訊息草稿、三點簡報大綱、或給自己的行動清單。

📝 測驗（單選）

問題：CODE 中哪個步驟是第二大腦真正創造價值的關鍵？

📌 重點回顧

  • Distill 讓未來的自己能快速提取
  • Express 才是系統存在的理由
  • 每次小循環都會強化你的第二大腦
Day 6 · 約 70–90 分鐘

為一人公司 / 多業務設計 PARA + 多公司財務基礎

🎯 學習目標

  • 根據真實業務設計專屬的 PARA 結構
  • 認識 Properties + Bases 如何支援多公司財務對帳
  • 建立「Inbox → 處理 → 歸檔」的日常流程

📖 白話解釋

一人公司通常同時跑多個業務。PARA 的優勢係「跨業務統一」：Projects 可以同時有不同公司的專案；Areas 放長期責任（尤其是「財務」）。

多公司財務對帳核心思路
用 Properties 為每筆交易加上 company、type、amount、status、date 等屬性。
之後用 Bases（官方核心功能）做成可篩選、可排序的儀表板，一眼睇到各公司待對帳項目、現金流、待收款。

建議在 02-Areas/財務 下建立：00-Inbox、01-交易紀錄、02-發票與收據、03-銀行對帳、04-公司總覽、05-每月對帳。

🛠️ 操作步驟

  1. 檢視你現有的 Projects，確保每個都有「明確目標 + 大概期限」
  2. 在 02-Areas 建立「財務」資料夾，並加入上述子資料夾
  3. 為常用 Area 建立「儀表板筆記」
  4. 建立一個「每週檢視」筆記模板
  5. 嘗試為 1–2 筆模擬交易筆記加上 Properties（company、type、amount、status）
  6. 設定固定時間（例如週日晚上）做 Inbox 清零與 Projects 狀態更新

⚠️ 常見錯誤

  • Projects 定義太模糊（「做行銷」不是專案）
  • Areas 與 Projects 混淆 → 問自己「有沒有明確結束日？」
  • Properties 命名不統一（有時 Company、有時 company）→ Bases 會失效
  • 不做定期檢視 → 系統會逐漸失效

✍️ 練習

完成你個人的 PARA 結構圖。在「財務」Area 建立基本資料夾。寫下你的「每週檢視」固定時間，並建立對應模板筆記。嘗試為兩筆交易加上標準 Properties。

📝 測驗（單選）

問題：一人公司使用 PARA 處理多公司財務時，最關鍵的基礎是什麼？

📌 重點回顧

  • PARA 可以同時服務多個業務
  • Properties + Bases 是多公司財務對帳的核心工具
  • 清晰的 Projects 定義 + 固定檢視習慣 = 系統長期有效
Day 7 · 約 90–120 分鐘

完整實戰專案：一人公司第二大腦 + 多公司財務啟動

🎯 學習目標

  • 從頭到尾完成一個真實可用的第二大腦專案
  • 建立多公司財務對帳的基本結構與 Properties 標準
  • 建立可長期執行的複習與維護節奏

🚀 完整實戰專案

請在 Obsidian 中實際完成以下步驟：

  1. 確認 Vault 名稱與四個 PARA 資料夾已建立
  2. 在 01-Projects 建立至少 3 個真實進行中的專案資料夾，每個裡面有一個「專案說明」筆記
  3. 在 02-Areas 建立「財務」「健康」「學習」「人脈/客戶」等領域
  4. 在「財務」下建立：00-Inbox、01-交易紀錄、02-發票與收據、03-銀行對帳、04-公司總覽、05-每月對帳
  5. 建立至少 3 筆模擬或真實交易筆記，統一使用以下 Properties：company、type、amount、date、status、category
  6. 為每間公司建立一個「公司總覽」筆記，作為日後嵌入 Bases 視圖的地方
  7. 建立 Inbox 處理流程與「每週檢視」模板
  8. 選擇一個現有長筆記，完成 Distill
  9. 用其中一個筆記實際 Express 一次（訊息草稿或行動清單）
  10. 打開 Graph View，欣賞你這一週建立的知識網絡

完成後的真實感覺：電腦螢幕顯示整齊的 PARA 資料夾與財務相關筆記，手寫筆記本放在旁邊記錄今日完成項目，自然光，高細節

📅 持續複習計劃

每日（5–10 分鐘）：捕捉有共鳴的內容到 Inbox，必要時快速加上 Properties
每週（20–30 分鐘）：清空 Inbox、更新 Projects 狀態、處理待對帳交易、把完成的移到 Archives
每月（40–60 分鐘）：做完整對帳筆記、更新各公司總覽、檢視 Resources 是否需要提煉

記住：學習的關鍵在於「如何提取記憶」。第二大腦的價值不在於你存了多少，而在於你需要時能多快、多準地找回並用出來。
